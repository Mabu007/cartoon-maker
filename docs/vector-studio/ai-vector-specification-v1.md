# Stage 13 — Optional external AI vector specification

No inference service, SDK, secret or mandatory AI. The factory can generate a complete specification locally. Character Factory > Advanced art > Import / prepare artwork > Native vectors > AI vector specification. Choose task, visual brief, target profile/style/views and rigid/spring/braid/fabric material. Copy or download the specification, separately download the machine-readable JSON Schema, or download the authored starter where available. Copy handles unavailable clipboard with selectable text. External AI is a separate manual action; nothing is uploaded by the app. Optional reference images are given separately to the external producer and must never be embedded in native JSON. The prompt contains numeric neutral rig anchors sampled from the actual runtime, not character names, images, audio or project data.

Structural specification uses z.toJSONSchema(NativeAssetPackage,{io:'input',reused:'ref'}), cached as text. Shared nativePackageLimits, nativeGeometryLimits, nativeDynamicsLimits, nativeCategorySlots and vectorArtworkLimits drive both validation and prompt. Explicit cross-field rules cover coverage, category slots, dependencies, mirror safety, topology, anchors, palettes and sparse deformation weights (not all representable in JSON Schema). Runtime validator always authoritative. Material values derive from lveMaterials. Actual renderer supports fixed head/neck/foot slots and normalized bones; reference rig anchors sampled with visualRigAnchors. Category capability table distinguishes supported hair and footwear; partial modular character, head-base face, shirt/jacket/trousers/dress and head accessory; unsupported new body-profile, eyes, nose, prop and environment native slots. No invented five-view geometry: full modular character five views exceed component cap, starter only front/three-quarter. No automatic cloth fitting, layered dress/jacket or separate eye/nose rig. Existing raster path remains.

Demonstration: authored Copper swept locks, Indigo tunic panel, Brass ear pendant fixtures adapted only in metadata, compatible profiles, materials and existing view subset. Not externally AI-generated; external generation inaccessible in this implementation. Copy prompt or download text, use an external producer, return strict JSON .sirvibe-assets; paste or import into quarantine, inspect and calibrate, install atomically, use on compatible character, save, audition with physics. For repair preserve exact error field, correct coverage/dependencies/weights/anchors/bounds/unsupported fields, resubmit complete JSON. Pasted output uses same strict validator and cannot mutate draft/library on failure. No code generation executed.

Generate distributable docs/fixtures with npm run docs:visual-assets (native-package-v2.schema.json, native-hair/shirt/accessory-ai-spec.txt, native-hair/shirt/accessory-authored-starter.sirvibe-assets). Generator runs against runtime each time; no manually duplicated structural schema. Tests validate prompt/schema alignment, category gating, rig values, starter view truthfulness, actual quarantine parser/recolor/install/export/apply/LVE/backup and repair hints. Browser QA and actual device/offline service worker/full audio export separate gates. Stop after Stage 13.
