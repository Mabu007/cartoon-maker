# Vector Character Studio architecture decisions

## 001. Add optional limb art at the renderer boundary

**Status** Accepted for the Stage 0 candidate. Release validation is tracked in the [stage ledger](stage-ledger.md).

The Stage 0 candidate restores PR #43's authored upper-arm, forearm, thigh and calf contours. Each region has a silhouette, inset shade and highlight in bone-local coordinates. The solved endpoints supply translation, rotation and length, and the character supplies width. The Pixi stage paints the contours using its existing bounded path cache. Character Studio's SVG fallback reads the same contour definitions and uses its own preview rig. Classic and original illustrated characters use the existing renderer for their style. Studio Sbu and Studio Zee presets select `anatomical-v1`.

The optional literal on `CharacterVisual` stays at schema version 1. Legacy characters omit the field. A profile change preserves an explicit choice, and opting out removes the field. Project, backup and asset package versions stay stable. Neither the raster slot definitions nor the project migration change for this recovery.

The body rig, MoCap compilation, dialogue and grip placement supply the same inputs to both art choices. The new curves are painted after pose resolution. A later art system can use the same boundary when it needs bone-local geometry.

## Current limitations

- Stage 0 changes four contours only. The native torso, hand, head, wardrobe and gait systems supply the rest of the character.
- The five saved views are authored facing choices. A mirrored view reuses the same art and may have a different active hand order. The SVG preview and Pixi stage have separate construction and wardrobe logic.
- Imported components can replace native art per view. The current SVG fallback uses its existing simple line fallback for the missing half of a partly imported limb. Appearance parity between that fallback and the stage is outside this recovery.
- The screenshots use built-in characters and props. The benchmark estimates CPU and command-submission cost on a software renderer. Device GPU, live webcam, varied lighting and long recording performance require on-device checks.

## 002. Consolidate the Stage 14 stack before adding new deformation

The Stage 14 branch contains the complete Stage 0–14 stack. Preserve its commit ancestry in the release. Past feature tips that were squash-merged already have their changes represented in the historical main commits. QA branches add preview-only build commands and a hanging-light bounds correction already present in the stack.

| Boundary | Current contract | Stage 15 integration point |
| --- | --- | --- |
| Canonical geometry | `VectorArtworkV1`, `VectorCommand`, `VectorMatrix` and `vectorDrawList` in `vectorArtwork.ts` define bounded path commands, paint tokens, pivots, units, transforms and material weights. `NativeBonePathCache` in `vectorArtworkRender.ts` converts supported bone-local art to Pixi paths. | Derive or import a mesh from validated artwork. Version cage weights, edge stitching and keyform data independently of the authored path commands. Preserve bounds and fallback behavior. |
| Identity and landmarks | `CharacterDefinition`, `CharacterVisual`, `characterIdentity.ts` and `visualRig.ts` carry anatomy, facial identity, rig calibration, profile and view information. | Bind mesh/keyform pivots to calibrated landmarks. Match the existing front, three-quarter, side, back-quarter and back view and mirror policies. |
| Motion and contacts | `evaluate`, `compileResolvedPerformance`, `resolveHandInteractions`, and `rig` own timeline sampling, capture constraints, custody and skeleton. `actorArt.ts` exposes the solved `ResolvedArtworkPose` snapshot with arms, legs, head, hands and facial performance. | Sample warp cages and blend shapes from the resolved pose. Pin wrists, feet and grip anchors. Keep authored actions, lip-sync and retargeting authoritative. |
| Existing deformation | `classifyArtworkPose`, `studioLimbArt.ts` and `nativeVectorBone.ts` select and bend contours. `deformRegion`, `deformGarmentPanels` and `secondarySurface.ts` apply bounded artwork displacement. | Attach denser deformations at the resolved artwork boundary. Retain older package, project and backup reads and prove portability with an offline restored fixture. |
| Creator tools and export | `CharacterFactory` auditions the shared Pixi renderer and can fall back to `NativeCharacterPreview`. `AssetWorkbench` manages local packages. `Stage`, `frameExport.ts` and the MediaRecorder exporter share `createRenderer`. | Author and preview keyforms in Character Factory with the same clock and drawing inputs as export. Define evidence for SVG fallback behavior, low-end memory and offline exports. |

This release has existing contour deformation and sparse physical offsets. Hierarchical warp cages, authored keyforms, mesh blend shapes, anatomical stitches and dynamic surface occlusion are Stage 15 work.
